# Bio-shop Bot v56.5

ระบบ Telegram Bot สำหรับสร้างไฟล์ VPN พร้อมเว็บไซต์ควบคุม โดยบอทและเว็บไซต์ใช้ฐานข้อมูล SQLite เดียวกันแบบเรียลไทม์

## ความสามารถล่าสุด

- เว็บไซต์ควบคุมผ่าน URL, IP หรือโดเมน
- จัดการเครือข่ายและแพ็กเกจจากเว็บไซต์
- แยกประเภทเครือข่ายเป็น:
  - **สินค้าเครือข่าย VPN ซื้อ** สำหรับเมนูซื้อ VPN
  - **สินค้าเครือข่าย VPN ทดลอง** สำหรับเมนูทดลองใช้ฟรี
- บอทจะแสดงเฉพาะเครือข่ายที่ตรงกับเมนูที่ใช้งาน
- เพิ่ม แก้ไข ลบ และเปิด–ปิดแพ็กเกจได้
- กำหนด Inbound ID แยกในแต่ละแพ็กเกจ
- กำหนด Template Port แยกในแต่ละแพ็กเกจได้ หรือเว้นว่างเพื่อใช้พอร์ตจาก Inbound
- กำหนดรายละเอียดแพ็กเกจและแสดงให้ลูกค้าดูก่อนตั้งชื่อไฟล์
- เว็บไซต์และบอทอ่านข้อมูลจากฐานข้อมูลเดียวกันทันที

## ลำดับการซื้อ VPN

```text
เลือกเครือข่ายสินค้า
→ เลือกแพ็กเกจ
→ แสดงชื่อแพ็กเกจ ราคา และรายละเอียด
→ ตั้งชื่อไฟล์
→ ระบุจำนวนวัน
→ กำหนด GB ตามเงื่อนไขแพ็กเกจ
→ สร้างไฟล์และส่งไปยัง DM
```

หลังเลือกรายการแพ็กเกจ ลูกค้าจะเห็นข้อมูลในรูปแบบใกล้เคียงนี้:

```text
✅ เครือข่าย: AIS
📦 แพ็กเกจ: AISPLAY
💳 ราคา: 3 เครดิต/วัน
📝 รายละเอียด:
ใช้งาน AISPLAY พร้อมโควตาตามแพ็กเกจ
```

ก่อนสร้างไฟล์ ระบบจะแสดงสรุปข้อมูลแบบเต็มเพื่อให้ตรวจสอบอีกครั้ง:

```text
📋 กรุณาตรวจสอบข้อมูลก่อนสร้าง

🌐 เครือข่าย: AIS
📦 แพ็กเกจ: AISPLAY
📌 ชื่อไฟล์: t
📅 จำนวนวัน: 2 วัน
💾 GB: 10
💳 ราคา: 6.00 เครดิต

ยืนยันการสร้างไฟล์หรือไม่?
```

## เงื่อนไข GB ของแพ็กเกจ

### 1. กำหนดจำนวน GB

ในหน้าแก้ไขแพ็กเกจ ให้เลือกตัวเลือก **กำหนดจำนวน GB** แล้วระบุค่า GB มากกว่า 0 ระบบจะใช้ค่านั้นทันทีและไม่ถามลูกค้าเรื่อง GB ซ้ำ เช่น:

```text
แพ็กเกจนี้กำหนดโควตา 5 GB
ระบบจะใช้ค่านี้โดยไม่ถามซ้ำ
```

ในกรณีนี้จะไม่ใช้ค่า **GB สูงสุดที่ผู้ใช้ใส่ได้**

### 2. ให้ผู้ใช้กำหนด

ในหน้าแก้ไขแพ็กเกจ ให้เลือกตัวเลือก **ให้ผู้ใช้กำหนด** แล้วระบุ **GB สูงสุดที่ผู้ใช้ตั้งได้** หากมากกว่า `0` ระบบจะแจ้งเฉพาะเพดาน เช่น:

```text
กรุณาระบุ GB ที่ต้องการใช้สำหรับทดลอง (สูงสุด 5 GB):
```

จะไม่แสดงคำว่า “หากไม่จำกัดพิมพ์ 0” เพราะมีเพดานบังคับอยู่แล้ว

### 3. ให้ผู้ใช้กำหนดโดยไม่จำกัด

ในโหมด **ให้ผู้ใช้กำหนด** หาก **GB สูงสุด = 0** ระบบจะแจ้ง:

```text
กรุณาระบุ GB ที่ต้องการใช้สำหรับทดลอง:
หากไม่จำกัดพิมพ์ 0
```

หากกรอกเกินเพดาน ระบบจะแจ้งช่วงค่าที่ถูกต้องและจะไม่สร้างไฟล์จนกว่าจะกรอกใหม่

## การทดลองใช้ฟรี

- ใช้เฉพาะเครือข่ายประเภท **เครือข่าย VPN ทดลองใช้งาน**
- รองรับการกำหนดแพ็กเกจทดลองและ Inbound ID
- รองรับโหมดรีเซ็ตสิทธิ์:
  - รีเซ็ตเวลา 00:00 พร้อมกันทุกคน
  - รีเซ็ตตามเวลาที่แต่ละคนเริ่มใช้งาน
- รองรับช่องทาง DM, กลุ่ม, กลุ่มที่กำหนด และรูปแบบผสม
- จำกัดสิทธิ์ทดลองเป็นจำนวนครั้งต่อคน

## การแก้ไขแพ็กเกจและรายละเอียด

- รายละเอียดแพ็กเกจรองรับข้อความหลายบรรทัดและแสดงพื้นที่แก้ไขขนาดใหญ่ขึ้น
- ตัวเลือก GB เป็นปุ่มเลือก 2 โหมดที่ไม่ใช้ค่าทับซ้อนกัน
- โหมดกำหนดจำนวน GB จะซ่อนช่อง GB สูงสุด
- โหมดให้ผู้ใช้กำหนดจะซ่อนช่อง GB ตายตัวและแสดงช่อง GB สูงสุด
- ระบบ API ตรวจสอบโหมดซ้ำอีกชั้นเพื่อป้องกันค่าผิดจากไคลเอนต์อื่น

## Package Template และการกำหนดพอร์ต

ในหน้าเว็บไซต์ไปที่ **จัดการเครือข่าย → จัดการแพ็กเกจ → เพิ่ม/แก้ไขแพ็กเกจ → เปิดใช้ Template** สามารถตั้งค่า Address, Port, Network, Host และ Path ได้แยกตามแพ็กเกจ

- **Port ว่าง:** ใช้พอร์ตจริงจาก `inbound.port` ของ Inbound ที่กำหนดให้แพ็กเกจ
- **Port ที่กำหนดเอง:** ใช้พอร์ตนั้นเป็นพอร์ตปลายทางของลิงก์ VPN โดยต้องเป็นจำนวนเต็ม `1–65535`
- ช่อง Address รับเฉพาะโดเมนหรือ IP ไม่ใส่พอร์ตรวมใน Address; ตั้งพอร์ตผ่านช่อง Port แยกต่างหาก
- ต้องเปิดใช้ Template จึงจะนำค่า Template Port มาใช้ หากปิด Template ระบบจะใช้พอร์ตจาก Inbound
- รองรับการเขียนพอร์ตใน URI ของ VLESS/Trojan และใน Base64 JSON field `port` ของ VMess โดยคง UUID/รหัสผ่านและค่าการเชื่อมต่ออื่นไว้
- ใช้กับทั้งการซื้อแพ็กเกจและทดลองใช้ฟรี ค่า Template Port ถูกเก็บใน `network_packages` และส่งออก/นำเข้าผ่านไฟล์สำรองและ Google Sheets

## รายละเอียดการยกเลิกและข้อความระหว่างซื้อ

ระหว่างขั้นตอนตั้งชื่อไฟล์ ระบบจะแจ้งข้อความยกเลิกและแสดงปุ่มยกเลิกให้ลูกค้าเห็น

ค่าเริ่มต้น **หน่วงปุ่มยกเลิก** คือ `1 วินาที` และปรับได้จากเว็บไซต์ โดยค่าหน่วงมีผลเฉพาะเวลาส่งปุ่มยกเลิก ไม่หน่วงคำถามหรือการทำงานของบริการ

เมื่อบอทถามข้อมูลที่ต้องพิมพ์ ระบบจะใช้ Telegram **ForceReply** และผูกคำตอบกับข้อความคำถามล่าสุดทั้งใน DM และกลุ่ม เพื่อให้ตอบกลับได้สม่ำเสมอจากทุกอุปกรณ์

หลังตรวจสอบข้อมูลและกด **ยืนยันการสร้าง** ระบบจะแก้ไขข้อความตรวจสอบเดิมให้เหลือสถานะการกระทำที่เลือก พร้อมสถานะการสร้าง/ส่งไปยัง DM โดยไม่ทิ้งปุ่มยืนยันหรือยกเลิกไว้ซ้ำซ้อน หากกด **ยกเลิก** ข้อความเดิมจะถูกแทนที่ด้วยสถานะยกเลิกทันที

ปุ่มยืนยันใช้ข้อความ **✅ ยืนยันการสร้าง** และปุ่มยกเลิกใช้ข้อความ **❌ ยกเลิก** ให้ตรงกันทั้งการซื้อ VPN และทดลองใช้ฟรี



## การอัปเดตค่าและการซิงก์ฐานข้อมูล

การบันทึกค่าจากเว็บไซต์จะถูกเขียนลงฐานข้อมูลทันที และซิงก์ไปยัง Google Sheets โดยอัตโนมัติเมื่อเลือก Google Sheets เป็นปลายทาง ในหน้า **สำรอง/คืนค่าข้อมูล** ยังมีปุ่มแยกสำหรับ **สำรองข้อมูลไป Google Sheets** และ **กู้คืนจาก Google Sheets**

ระบบตรวจสอบและปรับเส้นทางการบันทึกสำหรับค่าตั้งค่า เครือข่าย แพ็กเกจ ผู้ใช้ เครดิต โค้ดเครดิต และการนำเข้าฐานข้อมูลให้ใช้ฐานข้อมูลชุดเดียวกัน

## การเปลี่ยนฐานข้อมูล

ในเมนู **ฐานข้อมูล** มีปุ่ม **เปลี่ยนฐานข้อมูล** ให้เลือก **SQL Lite** หรือ **Google Sheet** โดยค่าเริ่มต้นคือในระบบ

เมื่อกด **ตกลงและรีเซ็ตข้อมูล** ระบบจะตรวจสอบค่าที่จำเป็นก่อน แล้วรีเซ็ตข้อมูลปัจจุบันทั้งหมด หลังจากนั้นให้อัปโหลดไฟล์ `.db` ผ่านเมนูนำเข้า ระบบจะนำข้อมูลไปใส่ฐานข้อมูลที่เลือกไว้

สำหรับ Google Sheet สามารถกรอกค่าในเว็บไซต์ได้โดยตรง:

- Google Sheet ID
- คำนำหน้าชีต
- Google Service Account JSON

หรือกำหนด `GOOGLE_SERVICE_ACCOUNT_JSON` ผ่าน Environment Variables ก็ได้ จากนั้นแชร์ Google Sheet ให้ Service Account มีสิทธิ์ Editor ระบบจะแยกข้อมูลแต่ละตารางเป็นชีต เช่น `users`, `clients`, `settings`, `networks`, `network_packages` และ `buy_log` ซึ่งสามารถเปิดดูและจัดการข้อมูลต่อใน Google Sheets ได้ โดยค่า Template ทั้งหมดจะอยู่ในชีต `BioShop_network_packages` ตามแถวแพ็กเกจ ได้แก่ `template_enabled`, `template_address`, `template_port`, `template_network`, `template_host` และ `template_path`

การเปลี่ยนฐานข้อมูลและการนำเข้าแบบ Google Sheet ใช้แพ็กเกจ `gspread` และ `google-auth`

## จัดการข้อมูลจากเว็บไซต์

เว็บไซต์รองรับ:

- ภาพรวมระบบ
- ตั้งค่าบอท
- จัดการเครือข่ายและแพ็กเกจ
- ผู้ใช้และเครดิต
- รายการสั่งซื้อ
- ประวัติการแก้ไข
- ฐานข้อมูล
- สำรอง/คืนค่าข้อมูล
- จัดการบัญชีเว็บไซต์

## การสำรองและคืนค่าฐานข้อมูล

หน้า **สำรอง/คืนค่าข้อมูล** จะแสดงปุ่มตามชนิดฐานข้อมูลที่กำลังเลือกใช้อยู่:

- เมื่อเลือก **SQLite** จะแสดงเฉพาะการดาวน์โหลดฐานข้อมูล SQLite `.db` และการอัปโหลดไฟล์ `.db` เพื่อแทนที่หรือรวมข้อมูลใน SQLite
- เมื่อเลือก **Google Sheets** การดาวน์โหลดไฟล์จะดึงข้อมูลล่าสุดจากชีตมาเป็นไฟล์ SQLite `.db` และการอัปโหลด `.db` สามารถเลือกแทนที่หรือรวมข้อมูล โดยผลลัพธ์จะถูกส่งกลับไปยัง Google Sheets และซิงก์เป็นฐานข้อมูลที่เว็บไซต์ใช้งาน
- ในส่วน Google Sheets มีปุ่ม **ซิงข้อมูล Sheets** สำหรับดึงข้อมูลจาก Google Sheets เข้าสู่เว็บไซต์ด้วยตนเอง โดยไม่เขียนทับชีตด้วยข้อมูลเก่าในเครื่อง
- ก่อนการกู้คืนหรือลบข้อมูล ระบบเก็บไฟล์สำรองเดิมไว้ในเครื่องเพื่อให้กู้คืนได้
- ปุ่ม **ลบฐานข้อมูล** ลบข้อมูลของชนิดฐานข้อมูลที่กำลังใช้งาน ต้องพิมพ์ `ยืนยันการลบ` ให้ตรงตามข้อความก่อนดำเนินการ การลบจะเก็บการตั้งค่าระบบ บัญชีเว็บไซต์ และการเชื่อมต่อฐานข้อมูลไว้ ส่วนเครือข่ายจะถูกสร้างกลับเป็นค่าเริ่มต้น AIS/TRUE
- ข้อมูล Template ทั้งหมดจะถูกเก็บไปพร้อมกับแพ็กเกจในตาราง `network_packages` และส่งออก/นำเข้าผ่าน Google Sheets ครบทุกคอลัมน์
- ก่อนดึงข้อมูลจาก Google Sheets ระบบตรวจสอบชีตและหัวคอลัมน์จำเป็น หากข้อมูลไม่ครบจะปฏิเสธโดยไม่ล้างฐานข้อมูลเดิม
- รองรับไฟล์สำรองรุ่นก่อนที่ยังไม่มีคอลัมน์ Template หรือ `template_port` โดยเติมค่าเริ่มต้นให้กับสำเนาที่นำเข้า/ส่งออก โดยไม่แก้ไฟล์ต้นฉบับ

## Environment variables

### จำเป็น

| ตัวแปร | รายละเอียด |
|---|---|
| `BOT_TOKEN` | Token ของ Telegram Bot |
| `ADMIN_IDS` | Telegram User ID ของผู้ดูแล คั่นด้วย comma |
| `XUI_URL` | URL ของ 3x-ui Panel |
| `XUI_API_TOKEN` | API Token ของ 3x-ui หากใช้งาน |
| `XUI_USERNAME` | Username ของ 3x-ui เมื่อไม่ใช้ API Token |
| `XUI_PASSWORD` | Password ของ 3x-ui เมื่อไม่ใช้ API Token |
| `WEB_ADMIN_PASSWORD` | รหัสผ่านเว็บไซต์จัดการ |
| `WEB_ADMIN_SECRET` | Secret สำหรับเซสชันเว็บไซต์ อย่างน้อย 32 ตัวอักษร |

### ตัวเลือก

| ตัวแปร | รายละเอียด |
|---|---|
| `DB_PATH` | ตำแหน่งฐานข้อมูล SQLite ค่าแนะนำ `/data/bot.db` |
| `WEB_ADMIN_ENABLED` | เปิดหรือปิดเว็บไซต์จัดการ |
| `WEB_ADMIN_USERNAME` | ชื่อผู้ใช้เว็บไซต์ |
| `WEB_HOST` | Host ของเว็บเซิร์ฟเวอร์ |
| `PORT` | Port ของเว็บเซิร์ฟเวอร์ |
| `PUBLIC_URL` | URL เว็บไซต์ที่ใช้แสดงในบอท |
| `WEB_COOKIE_SECURE` | ใช้ Secure Cookie เมื่อเป็น HTTPS |
| `TRUEMONEY_WALLET_PHONE` | เบอร์รับซอง TrueMoney |

ดูรายการตัวแปรทั้งหมดได้ที่ `env.example`

## การ Deploy บน Railway

1. อัปโหลดไฟล์ทั้งหมดไว้ที่ root ของ Repository
2. ตั้ง Environment variables
3. ใช้ Start Command:

```text
python main.py
```

4. ใช้ Dockerfile ที่อยู่ใน root
5. ผูก Volume ที่ `/data` เพื่อเก็บฐานข้อมูลถาวร
6. Health check ใช้ `/health`

ไม่ใช้ `uvicorn main:app` เพราะ `main.py` เป็นตัวเริ่มทั้ง Telegram Bot และเว็บไซต์

## การดึงข้อมูลและเปลี่ยนฐานข้อมูล

ในหน้า **สำรอง/คืนค่าข้อมูล** ปุ่ม **กู้คืนจาก Google Sheets** จะนำข้อมูลจากชีตที่เชื่อมต่อมาแทนที่ข้อมูลในฐานข้อมูลภายใน โดยระบบสร้างไฟล์ `DB_PATH.before-google-sheet-restore.db` ไว้ก่อนทุกครั้ง หากชีตไม่ครบตารางหลักหรือขาดหัวคอลัมน์สำคัญ ระบบจะไม่เริ่มกู้คืน

เมื่อเชื่อมต่อฐานข้อมูลใหม่ ค่าเริ่มต้นคือดึงข้อมูลจากฐานที่มีอยู่ หากต้องการล้างข้อมูลเดิมต้องเลือก **รีเซ็ตข้อมูลเดิมก่อนเชื่อมต่อ** โดยข้อมูลเดิมจะไม่ถูกเก็บไว้ในฐานที่ใช้งานแล้ว แต่มีไฟล์สำรองให้กู้คืนได้

## อัปเดตเครดิตจาก Google Sheet

เมื่อแก้ค่า `credit` ในชีต `BioShop_users` ระบบจะตรวจสอบและดึงค่าใหม่กลับเข้า SQLite ก่อนอ่านยอดเครดิต ทำให้ยอดที่เว็บและบอทแสดงตรงกับฐานข้อมูลที่เลือก

## รีเฟรชค่าทุกประเภทจาก Google Sheet

ระบบไม่ได้รีเฟรชเฉพาะยอดเครดิตอีกต่อไป แต่ตรวจสอบค่าจากตารางทั้งหมด เช่น ผู้ใช้ เครือข่าย แพ็กเกจ การตั้งค่า เครดิต โค้ดเครดิต และประวัติรายการ ก่อนเว็บหรือบอทอ่านข้อมูล โดยมีการหน่วงเวลาเพื่อไม่เรียก Google Sheet API ซ้ำเกินจำเป็น

## การดึงข้อมูลจาก Google Sheet ครั้งแรก

เมื่อพบข้อมูลเดิมใน Google Sheet ระบบจะดึงข้อมูลมาใช้เป็นค่าเริ่มต้น ไม่เขียนทับด้วย SQLite ว่าง และจะรีเฟรชค่าที่แก้ใน Sheet กลับเข้าเว็บและบอทตามรอบที่ตั้งไว้

## การคงค่าฐานข้อมูลที่เลือก

ระบบเก็บ backend, Google Sheet ID, คำนำหน้าชีต และ Service Account configuration แยกจากข้อมูลที่นำเข้า เพื่อไม่ให้การดึงข้อมูล การรีโหลดเว็บ หรือการ restore เปลี่ยนกลับไปใช้ฐานข้อมูลภายในโดยอัตโนมัติ


## v56.5 — Package Template Port Override

- เพิ่มช่อง **Port (พอร์ตปลายทาง)** ในส่วน Package Template บนเว็บไซต์
- กำหนดพอร์ตเป็นจำนวนเต็ม `1–65535`; เว้นว่างเพื่อใช้ `inbound.port` จาก 3x-ui
- Template Port จะมีผลเมื่อเปิดใช้ Template เท่านั้น; เมื่อปิด Template จะกลับไปใช้พอร์ต Inbound
- ใช้กับ VLESS/Trojan URI และ VMess Base64 JSON โดยเขียนพอร์ตหลังจากปรับ Address / Network / Host / Path เพื่อให้ค่าที่เลือกเป็นพอร์ตสุดท้ายจริง
- เพิ่มคอลัมน์ `template_port` ในฐานข้อมูลพร้อม Migration; ค่าเริ่มต้น `0` หมายถึงใช้พอร์ต Inbound
- รวม `template_port` ใน SQLite backup, Google Sheets export/import และ package merge; ไฟล์สำรองรุ่นเก่ายังคงนำเข้าได้โดยอัตโนมัติ
- เพิ่ม Regression tests สำหรับพอร์ต Template, พอร์ต Inbound fallback, Template ปิด, VMess/VLESS และการสร้างลิงก์

## v56.4 — Final Inbound Port Enforcement (ค่าเริ่มต้น)

- ระบบอ่าน `inbound.port` จาก Inbound ที่แพ็กเกจเลือก และส่งค่าเดียวกันไปตลอดขั้นตอนสร้างลิงก์
- หาก Template ไม่กำหนด Port ระบบจะเขียนพอร์ตจาก Inbound เป็นขั้นตอนสุดท้าย
- VLESS จะใช้พอร์ตใน URI endpoint ส่วน VMess จะใช้พอร์ตใน Base64 JSON field `port`
- ยังคง UUID / VMess `id`, Address ที่กำหนดใน Template, Network, Host, Path และค่าการเชื่อมต่ออื่น ๆ ตามเดิม
- ใช้ขั้นตอนเดียวกันทั้งการซื้อแพ็กเกจและทดลองใช้ฟรี หากยืนยันพอร์ตไม่ได้จะไม่ส่งลิงก์ที่ไม่ถูกต้อง
- ทดสอบด้วย Unit tests ครอบคลุม VLESS, VMess, Template เปิด/ปิด และการสร้างลิงก์ผ่าน `generate_link()` (`python -m unittest discover -s tests -v`)

## v56.3 — Inbound Port Fix

- ลิงก์ที่ส่งให้ผู้ใช้จะใช้พอร์ตจาก `inbound.port` ของ 3x-ui Inbound ที่แพ็กเกจเลือกไว้เสมอ
- ลิงก์จาก Panel API จะถูก normalize เฉพาะพอร์ต โดยรักษา UUID/รหัสผ่าน, Address, Query และ Fragment
- VMess จะปรับเฉพาะฟิลด์ `port` ใน Base64 JSON และรักษา `id` เดิม
- หากไม่สามารถอ่าน Inbound หรือพอร์ตไม่ถูกต้อง ระบบจะหยุดสร้างลิงก์แทนการส่งค่าพอร์ตที่ไม่ยืนยัน
